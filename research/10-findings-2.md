# Dossier 2: Windows desktop OS integrations

Researcher scope: Audio capture, global hold/double-tap input, cursor insertion, waveform overlay, media ownership, and worker lifetime | Goal context: Approval-ready separate native Windows architecture and implementation plan for fully local Far Flow dictation | Date: 2026-10-27

These are source-level findings, not an architecture recommendation or Windows test results. All sources were accessed on 2026-10-27. Microsoft Learn generally exposes a **last updated** date rather than an original publication date; those dates are identified below. An undated API reference is not assigned a guessed publication date. “Design inference” identifies a proposed interpretation beyond the documented API contract.

## Findings

### F2.1 — Fn is not a portable Windows dictation trigger

- **Claim:** Microsoft's keyboard-remapping documentation explicitly excludes the Fn key in most cases, so universal standalone-Fn support is not an official Windows guarantee.
- **Source:** [PowerToys Keyboard Manager](https://learn.microsoft.com/en-us/windows/powertoys/keyboard-manager) — primary/official Microsoft product documentation — last updated 2026-06-08.
- **Confidence:** High for the documented limitation; Medium for explaining any individual keyboard's mechanism without OEM evidence.
- **Notes:** The same document permits remapping F1–F24 and notes hardware-dependent keys and applications with interfering hooks. Fn's handling at firmware/keyboard-controller level is described in [a Microsoft-hosted Q&A answer about a ThinkPad](https://learn.microsoft.com/en-us/answers/questions/5806673/fn-key-stuck-unable-to-do-any-writing) — forum/Microsoft MVP answer, 2026-03-03; that is not an API contract or an all-PC hardware survey. **Design inference:** a configurable ordinary key/chord and an onboarding event-detection test are needed if Fn is offered as an optional hardware-dependent binding. No MSI/RTX 3070-class Fn behavior has been physically tested here.

### F2.2 — RegisterHotKey alone does not expose the release edge needed for hold-to-talk

- **Claim:** RegisterHotKey's documented event is WM_HOTKEY on a matching press, rather than a corresponding global key-release notification.
- **Source:** [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) — primary/official Win32 API reference — last updated 2024-06-12.
- **Confidence:** High.
- **Notes:** MOD_NOREPEAT suppresses auto-repeat; conflicting registrations can fail; F12 is debugger-reserved and Windows-key chords are OS-reserved. [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/ms644985(v=vs.85)) — primary/official archived Win32 API reference, last updated 2018-03-30 — explicitly receives WM_KEYDOWN, WM_KEYUP, WM_SYSKEYDOWN, and WM_SYSKEYUP. **Design inference:** hold/release and double-tap recognition require an edge-aware input path and a state machine that ignores repeats, rather than treating repeated WM_HOTKEY notifications as separate taps. A low-level hook is a candidate, not a documented requirement; the hook documentation recommends considering Raw Input for monitoring. Trigger suppression, AltGr/layout interactions, other hooks, lost release on lock/suspend, and reserved chord behavior remain Windows acceptance tests.

### F2.3 — Low-level keyboard hooks can disappear after slow callbacks

- **Claim:** Windows can silently remove a WH_KEYBOARD_LL hook when its callback exceeds the allowed timeout.
- **Source:** [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/ms644985(v=vs.85)) — primary/official archived API reference — last updated 2018-03-30.
- **Confidence:** High.
- **Notes:** On Windows 10 version 1709 and later, the documented timeout cap is 1,000 ms; the installing thread needs a message loop. Microsoft advises a dedicated thread that dispatches work and immediately returns. It also warns that GetAsyncKeyState inside the callback sees the state before the current transition has updated. [KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct) — primary/official, last updated 2021-04-01 — carries down/up and injected-event flags plus `time`. [GetMessageTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime) — primary/official, last updated 2024-02-22 — defines that time as milliseconds since startup when the message was created, with wraparound. **Design inference:** use event timestamps and wrap-safe deltas for gesture recognition, not delayed UI-dispatch receipt times; ignore the app's marked/injected output. This is a Windows message timestamp, not a guaranteed measurement of the physical switch's electrical actuation. Do no inference, IPC waits, rendering, or disk work in the hook callback.

### F2.4 — WASAPI exposes the actual shared-engine format for capture

- **Claim:** GetMixFormat returns an endpoint's shared-engine stream format, and shared-mode initialization on that same endpoint accepts that returned format.
- **Source:** [IAudioClient::GetMixFormat](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat) — primary/official Win32 API reference — last updated 2025-09-05.
- **Confidence:** High.
- **Notes:** [Capturing a Stream](https://learn.microsoft.com/en-us/windows/win32/coreaudio/capturing-a-stream) — primary/official, last updated 2021-01-06 — demonstrates `GetDefaultAudioEndpoint(eCapture, eConsole)`, GetMixFormat, shared-mode initialization, and IAudioCaptureClient. It is microphone capture, distinct from output loopback. **Design inference:** query the selected/default microphone's actual rate/channel/sample representation, then normalize to the ASR contract, for example mono 16,000 Hz; do not hard-code incoming 44,100 or 48,000 Hz. [Audio Resampler DSP](https://learn.microsoft.com/en-us/windows/win32/medfound/audioresampler) — primary/official, last updated 2021-06-30 — supports PCM/float rate and channel conversion. **Counterevidence:** [AUDCLNT_STREAMFLAGS_AUTOCONVERTPCM](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audclnt-streamflags-xxx-constants) — primary/official, last updated 2021-01-06 — provides engine-side conversion as another route. Explicit application-side conversion is a controllability/testing choice, not a universal WASAPI necessity. Neither route's quality/latency has been measured here.

### F2.5 — Direct WASAPI clients must implement endpoint-change routing

- **Claim:** Applications using WASAPI/MMDeviceAPI directly are responsible for responding to default-device, endpoint-removal, and format-change notifications rather than receiving automatic high-level stream routing.
- **Source:** [Stream Routing](https://learn.microsoft.com/en-us/windows/win32/coreaudio/stream-routing) — primary/official Microsoft Core Audio documentation — last updated 2021-01-06.
- **Confidence:** High.
- **Notes:** [Communications audio format capabilities](https://learn.microsoft.com/en-us/windows/win32/coreaudio/communications-audio-format-capabilities) — primary/official, last updated 2025-08-26 — documents that opening a Bluetooth microphone may change audio mode/format. Classic HFP uses mono 8,000 or 16,000 Hz on Windows 11; documented LE communications rates include 16,000, 24,000, and 32,000 Hz. Thus 44.1/48 kHz coverage alone is insufficient. [IAudioCaptureClient::GetBuffer](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer) — primary/official, last updated 2025-09-05 — provides frame count, device/QPC positions, discontinuity/timestamp-error flags, and invalidation errors. **Design inference:** reconnect through a capture coordinator, rebuild the converter on format changes, segment/mark discontinuities, and cancel/reset gesture and media ownership on lock/suspend/device loss. Do not reinterpret old-rate buffers under the new rate. Microphone privacy denial and unplug/reconnect must be explicit test cases; no seamless-recovery guarantee was found.

### F2.6 — UIA's Value operation is not a caret-insertion primitive

- **Claim:** IUIAutomationValuePattern::SetValue sets an element's value and does not accept a caret position or selected-range insertion argument.
- **Source:** [IUIAutomationValuePattern::SetValue](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationvaluepattern-setvalue) — primary/official Win32 API reference — last updated 2024-02-22.
- **Confidence:** High.
- **Notes:** [TextPattern Overview](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-textpattern-overview) — primary/official .NET Framework documentation, last updated 2021-09-15 — explicitly says TextPattern cannot insert/modify text. [Current native Text/TextRange guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange) — primary/official, last updated 2025-07-14 — describes content retrieval, ranges, caret/selection and recommends coexisting Value support. This contradicts old sample wording implying TextPattern and ValuePattern are mutually exclusive; do not repeat that assertion. **Design inference:** use UIA to inspect/validate targets and selection where supported; never use SetValue as generic append-at-cursor, or read/concatenate/write whole-document text as a universal fallback. Whole-value replacement can overwrite content/selection/formatting. [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput) — primary/official, last updated 2023-05-19 — specifically supports voice-recognition-style Unicode input through KEYEVENTF_UNICODE/VK_PACKET to the foreground application. This still requires compatibility tests for browsers, rich editors, Electron, terminals, IMEs, and non-BMP text.

### F2.7 — Ordinary SendInput cannot cross upward through integrity levels

- **Claim:** SendInput is subject to UIPI and only injects into equal- or lower-integrity applications.
- **Source:** [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) — primary/official Win32 API reference — last updated 2021-10-13.
- **Confidence:** High.
- **Notes:** A zero/partial insertion count must be handled; the error information does not identify UIPI as the cause. [Assistive technology security](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview) — primary/official, last updated 2026-02-19 — describes separate trusted UIAccess requirements, Authenticode signing and secure installation location, restricts its intended use to assistive technology, and does not make it a general secure-desktop bypass. **Design inference:** an ordinary as-user Far Flow process should expose copy/history recovery for elevated targets and exclude secure desktops instead of defaulting to administrator/UIAccess. [UIA IsPassword](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-automation-element-propids) — primary/official, last updated 2025-07-14 — identifies protected/password content; it does not promise that all injected input into password fields is OS-blocked. Password/secure-target suppression is therefore an explicit product rule: block automatic insertion/context capture on known protected fields, and fail closed when trustworthy target validation is unavailable. No reliable universal password detector across arbitrary apps was found.

### F2.8 — Unicode injection is directed to whichever thread is foreground at delivery

- **Claim:** KEYEVENTF_UNICODE delivery targets the foreground thread's input queue, rather than an HWND supplied by the caller.
- **Source:** [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput) — primary/official Win32 API reference — last updated 2023-05-19.
- **Confidence:** High for routing; Medium for the proposed cross-application recovery policy.
- **Notes:** [GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo) — primary/official, last updated 2021-10-13 — can inspect another foreground thread but warns handles may be invalid during activation loss. **Design inference:** capture target identity/focus at recording start, revalidate immediately before delivery, abort to retained history/copy on a changed or uncertain target, and do not automatically retry after ambiguous partial delivery. Clipboard paste is a separate opt-in/tested fallback: [OpenClipboard](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard) — primary/official, last updated 2024-02-22 — serializes clipboard modification while open; [GetClipboardSequenceNumber](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber) — primary/official, last updated 2021-06-29 — changes when contents change/empty, with delayed-render caveats. Snapshot supported formats and only restore while holding the clipboard open if the sequence still matches the app's temporary content; never overwrite a later user copy. No atomic focus-check + paste + consumption-acknowledgment API was found. [Windows Terminal interaction settings](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/interaction) — primary/official, last updated 2025-10-21 — warns that pasted newlines can execute shell commands. “Never append Enter” is necessary but insufficient: multiline terminal insertion also needs review/copy-only handling; Ctrl+V is configurable and not universal.

### F2.9 — A top-level HWND can be shown without taking foreground activation

- **Claim:** WS_EX_NOACTIVATE prevents a top-level window from becoming foreground when clicked.
- **Source:** [Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) — primary/official Win32 reference — last updated 2025-07-14.
- **Confidence:** High.
- **Notes:** WS_EX_TOOLWINDOW excludes the toolbar from taskbar/Alt+Tab, and WS_EX_TOPMOST keeps it above non-topmost windows while inactive. NOACTIVATE alone is not a guarantee against code calling activation APIs. **Design inference:** use a dedicated waveform HWND with these appropriate styles, nonactivating show/move calls, and explicit mouse hit-testing/drag behavior; keep settings/history in a separate accessible interactive window. [WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged) — primary/official, last updated 2025-07-14 — documents per-monitor moves/scale changes and a suggested rectangle, with an example using SWP_NOACTIVATE. Persist monitor-aware placement and clamp against current work areas after disconnect/rearrange; test 100%/125%/150%/200% mixed-DPI, negative virtual coordinates, taskbar positions and touch. WS_EX_TRANSPARENT's documented paint ordering is not a general promise of mouse click-through. No proof was found that an arbitrary WinUI window configuration alone supplies all these behaviors without HWND interop.

### F2.10 — GSMTC is public, but only exposes cooperating media sessions

- **Claim:** The public GlobalSystemMediaTransportControlsSessionManager exposes playback sessions that participate in Windows SystemMediaTransportControls.
- **Source:** [App capability declarations](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/app-capability-declarations) — primary/official — last updated 2026-10-02; [GSMTC session class](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession?view=winrt-26100) — primary/official API reference — publication/update date not displayed, accessed 2026-10-27.
- **Confidence:** High for API availability and participant boundary; Medium for deployment combinations pending Windows tests.
- **Notes:** The class is documented from Windows 10 version 1809/build 17763, UniversalApiContract v7. RequestAsync lists `globalMediaControl`; the capability documentation places it in **general-use**, with `uap7:Capability`, rather than restricted capabilities. This is not evidence for universal control of all audio-producing processes. **Disconfirming evidence:** [Microsoft's C++/C# console example](https://devblogs.microsoft.com/oldnewthing/20231108-00/?p=108980) — primary/official Microsoft engineering blog, published 2023-11-08 — requests the manager from an ordinary console program. It weakens any blanket MSIX-only claim. The current capability guide distinguishes Medium IL, packaged, and AppContainer apps. The retrieved official pages do not give an unambiguous packaged/unpackaged GSMTC permission matrix or a mandatory user permission-dialog flow. Record capability manifest requirements where applicable, and test the exact intended packaged and unpackaged release configurations as standard user.

### F2.11 — GSMTC pause is a fallible request, not a pause-ownership token

- **Claim:** TryPauseAsync returns a Boolean indicating whether its pause request succeeded.
- **Source:** [GSMTC TryPauseAsync](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession.trypauseasync?view=winrt-26100) — primary/official API reference — publication/update date not displayed, accessed 2026-10-27.
- **Confidence:** High for the Boolean request contract; Medium for ownership inference.
- **Notes:** [GSMTC session class](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession?view=winrt-26100) — primary/official, undated — supplies source AppUserModelId, playback info/events, and separate TryPauseAsync/TryPlayAsync/TryTogglePlayPauseAsync methods. [GetCurrentSession](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssessionmanager.getcurrentsession?view=winrt-26100) — primary/official, undated — identifies the session Windows believes the user most likely wants to control, not a retained recording-owned session. **Design inference:** hold the exact selected session plus app identity, pre-pause Playing state, successful explicit pause result, recording generation and observed state continuity; resume explicitly on that same still-valid session only under the chosen ownership policy. Do not send a global play/pause toggle or resume the newly current session. AppUserModelId alone is not documented as a unique session-instance identity. No official causal token distinguishes “paused by Far Flow” from a simultaneous user/other-controller pause; events have state but no documented command-origin tag. User intervention, session replacement/disappearance and false/throwing Try* calls must invalidate/restrict resume ownership and be tested.

### F2.12 — Kill-on-close Job Objects can bind worker lifetime to the owner

- **Claim:** JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE terminates associated processes when the last handle to that job closes.
- **Source:** [JOBOBJECT_BASIC_LIMIT_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) — primary/official Win32 API reference — last updated 2022-08-23; [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) — primary/official — last updated 2025-07-14.
- **Confidence:** High.
- **Notes:** [ExitProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-exitprocess) — primary/official, last updated 2022-11-01 — explicitly says parent exit does not terminate child processes. The job association must actually succeed; children normally inherit membership unless permitted to break away. **Design inference:** the UI should own a noninherited job handle, create a local inference worker suspended, assign it before executing model code, then resume; fail closed if assignment fails. Avoid leaking/duplicating the job handle into workers, or the “last handle” condition is defeated. Graceful shutdown/cancel can precede bounded forced cleanup. [WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close) — primary/official, last updated 2025-07-14 — normally destroys a window, not by itself every process. Close-to-quit therefore needs an explicit app shutdown path that releases microphone/hooks/media state and exits the owner; minimize may preserve the running owner/model by product policy. A hidden window, tray icon or minimized window does not itself release model memory. Crash/Task Manager termination, nested-job launchers, blocked shutdown, GPU context release and no-orphan/no-resident-model measurements require Windows tests.

## Gaps — what I could not find

- No attached Windows device, input logger, elevated target, audio endpoint, Bluetooth headset or GPU was available to validate behavior; there are no Windows pass/fail or performance results in this dossier.
- No official universal Fn virtual-key/scan-code contract, OEM matrix, or proof that a specific MSI laptop reports standalone Fn to user-mode hooks. The firmware explanation is weaker forum evidence, whereas the nonportable outcome is official PowerToys documentation.
- No universal guarantee that RegisterHotKey plus polling provides lossless hold/release gestures. Raw Input versus WH_KEYBOARD_LL suppression, coexistence and lock-screen recovery need a Windows spike.
- No guaranteed physical-actuation precision for keyboard message timestamps, and no verified event-to-overlay latency or double-tap threshold for this product. Hook timestamps and audio QPC positions are distinct clock representations; calibration must be designed/tested if alignment is needed.
- No all-device guarantee of 16 kHz capture initialization, Bluetooth mode stability, seamless default-endpoint recovery, communications-category suitability for dictation, or resampler quality/latency. Microsoft's Bluetooth documentation itself includes Windows-build-specific limitations.
- No cross-application atomic API combining target focus/selection validation and insertion with a text-consumed acknowledgment. Full arbitrary OLE/private/delayed-render clipboard preservation is not proven by the sequence-number API; a plain-text-only backup must not be described as lossless preservation.
- No universal password-field detector or ordinary-process secure-desktop insertion support; password suppression and safe unknown-target behavior must be explicit product rules.
- No official guarantee that Unicode VK_PACKET works identically in every terminal, editor, game, remote session or custom text control. No evidence that Ctrl+V universally means paste. No safe basis for automatically appending Enter, executing terminal lines, or silently retrying uncertain delivery.
- No clear official single-page matrix for GSMTC capability enforcement across packaged Medium IL, AppContainer, and unpackaged desktop apps. No proof all media apps register sessions. No causal pause-ownership API or unique session-instance key was documented.
- No evidence that merely closing a UI window reclaims an inference worker. Job-handle containment, release of GPU resources and process-exit deadlines need integration measurements.

## Disconfirming evidence check

- **Attempt to disprove “WASAPI mandates application-side conversion”:** found AUTOCONVERTPCM, which inserts conversion in the audio engine. Native-format capture with explicit resampling remains an option; it must be labeled design inference.
- **Attempt to disprove “TextPattern and ValuePattern can never coexist”:** current native Text/TextRange guidance explicitly recommends both. The stronger old .NET mutual-exclusion statement was rejected; the no-TextPattern-insertion and no-caret-argument-SetValue facts remain.
- **Attempt to disprove “GSMTC needs MSIX”:** Microsoft's console sample shows use without showing an MSIX project/manifest. This is evidence against a blanket packaging claim, but not proof of every distribution configuration; the uncertainty is retained.
- **Attempt to disprove “low-level hook is the only viable input path”:** the official hook reference recommends considering Raw Input and warns about silent removal. No exclusivity claim is made.
- **Attempt to disprove “password fields are automatically protected against all SendInput”:** no such official guarantee was found; Microsoft documents integrity-level limits and UIA protected-field metadata separately. Blocking dictation into protected/unknown targets is identified as a product policy.
- **Attempt to disprove “no appended Enter makes terminals safe”:** official Terminal documentation states pasted newlines can execute commands. Multiline payload handling is a separate unresolved behavior/test gate.

## Research limitations

- A read-only Python HTTPS metadata request failed because this macOS Python runtime could not validate the local certificate chain; no trust settings were changed. Source content and dates above came from the browser/search tool's direct Microsoft page reads instead.
- References have been checked for content support by this researcher, but await independent validation. No app implementation, Mac repository edits, OS-setting changes, repository creation, or publishing was performed.
