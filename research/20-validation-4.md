### F4.3 — Gesture portability and thresholds

- **Verdict:** PARTIAL.
- **Independent source:** [FnGestureTests](https://github.com/Farazs27/far-flow/blob/ccb628adbeea97ed898c35f1f83b21188815c32b/FarFlowTests/FarFlowTests.swift) and [ShortcutService event adapter](https://github.com/Farazs27/far-flow/blob/ccb628adbeea97ed898c35f1f83b21188815c32b/FarFlow/App/ShortcutService.swift), fixed baseline. Independent searches: press/release/expire tests; adapter's `pendingStopDeadline` scheduling and uptime use. A second search for literal 0.22/0.35 outside the cited state-machine implementation found no separate exact-boundary tests/specification.
- **Correction / contradiction:** Tests explicitly expect `.start` on the first press at time 0. The 0.22-second constant must not be described as a delay before recording starts: it classifies release/hold behavior. A short release waits for the second-tap opportunity; a second press can lock; a later press stops locked recording. Existing tests corroborate these outcomes but do not independently pin both exact threshold boundary values. Add tests immediately below/at/above each threshold, repeat down, lost release, delayed callback and clock wrap before translating to Windows. Portability remains a proposal, not an executed cross-platform result.
- **Source-quality flags:** Primary tests and adapter are current and nonpromotional. Test definitions are design evidence, not executed results; exact numeric claims are supported only by the original implementation until explicit independent boundary fixtures exist.

## What the researcher missed

- **Target capture timing matters:** AppModel captures the final insertion target at recording release, deliberately allowing cursor movement while speaking, then rejects later changes during processing. A Windows plan that freezes the target only at recording start changes behavior. Record this as an approval decision, not automatic parity.
- **Gesture activation is immediate:** avoid a 220 ms startup delay introduced by the phrase “hold threshold.” Exact timing and cancellation cases need explicit tests.
- **“All MLX is Mac-only” is obsolete:** upstream Linux CPU/CUDA support exists; that does not validate Windows or the pinned app build.
- **Backup formats differ:** full UserData backup and dictionary-only JSON need separate schemas/fixtures. A source-code date-strategy audit is not cross-language import validation; test real field encodings using synthetic fixtures.
- **Coverage gaps:** the existing text tests do not pin all stated noncascading/Unicode rules; existing input/media tests include fakes and cannot certify cross-editor insertion or physical keyboard behavior.
- **Other native dependencies:** private MediaRemote/system Perl transport, Core Audio capture, event taps, platform login registration, file panels, keyboard sounds and SF Symbols each need a Windows replacement or explicit omission. The model migration alone is insufficient.
- **Data safeguards:** privacy docs say the database has no separate app encryption; retention/off/clearing semantics and raw-plus-cleaned deletion need portability decisions. Do not advertise migration as encrypted or losslessly equivalent without schema and storage validation.
- **Provenance:** the public fixed revision is the audit boundary. Build/run results and screenshots should cite the actual revision and environment; neither tracked test definitions nor source-check CI constitute a fresh native test pass.
